## 3. 文件命名格式分析

### 3.1 主流命名规范

约 95% 的 `code/` 文件遵循以下格式之一：

- `{前缀}{题号}.{扩展名}` — 如 `P1001.cpp`, `CF1234A.cpp`
- `{前缀}{题号}({版本号}).{扩展名}` — 如 `P1002(2).c`, `B3367(2).cpp`
- `{前缀}{题号}_{版本号}.{扩展名}` — 如 `P1277_2.cpp`, `P10634_3.cpp`

### 3.2 命名不一致问题

| 问题 | 示例 | 影响范围 |
|------|------|----------|
| **版本号格式不统一** | `(2)` vs `_2` vs `_3` vs `(3)` | 75+ 个文件用 `_N`，265+ 个用 `(N)` |
| **大小写不统一** | `cf576c.cpp` vs `CF576C` 不存在；`p3769(2).cpp` vs `P3769` | 8 个文件小写前缀 |
| **前缀风格不统一** | `abc302.cpp` vs `ATabc308.cpp` vs `AT069D.cpp` vs `AGC010F.cpp` | AtCoder 题用了至少 4 种前缀格式 |

### 3.3 建议的统一格式

```
{前缀}{题号}.{扩展名}          — 单版本
{前缀}{题号}_v{版本}.{扩展名}  — 多版本（v1, v2, v3...）
```

其中前缀统一为大写。如 `CF576C.cpp`（不存在，但可新建规范目录）。

### 4.2 多版本的原因推测

| 对比 | 结论 |

**结论：绝大多数多版本文件是同一题的不同解法或不同提交版本，属于有意义的保留，但缺少规整的清理（应只保留最佳版本或命名版本号）。** 极少数（如 P1840 有 `.c` 和 `.cpp` 各两个版本）可能存在冗余。

## 6. 必须读取代码内容才能判断的问题

这类问题无法仅通过文件名确定，需进一步逐文件检查：

### 6.1 文件名与内容题号是否一致
抽样验证情况：
- `P1002(2).c`、`P1002(3).c`、`P1004(2).c`、`P1016(2).cpp` 内容中**未嵌入题号注释**，无法自动验证文件名与内容是否一致
- 仅有部分中文命名文件（如 `左偏树合并模板2.cpp` → P2713）可通过题号注释确认
- **需要验证全部 2773 个文件中是否有个别文件放错了题号**

### 6.2 `.c` 和 `.cpp` 版本的关系
约 30+ 道题同时有 `.c` 和 `.cpp` 版本，需要确认：
- 是否仅语言不同（保留两者有意义）
- 还是同一语言的重复提交（应清理）

### 6.3 多版本中的"最佳版本"
每个有多版本文件的题，需确定哪个是正确/最优解，其余可归档或删除。

### 6.4 转码问题
`P1281(2）.c` 使用了全角 `）`，读取内容时不影响编译（注释和字符串外），但文件名在部分系统可能引发问题。

## 8. 整理建议规则

### 8.1 文件命名规范

```
{前缀}{题号}.{扩展名}              — 单一版本
{前缀}{题号}_v{数字}.{扩展名}      — 多版本（v1, v2, v3...）
{前缀}{题号}_alt.{扩展名}          — 不同语言的替代实现
```

- 前缀统一**大写**：`P` / `CF` / `AT` / `SP` / `LOJ` / `UVA` / `HDU`
- 版本号统一使用 `_v2` 格式，取代 `(2)` 和 `_2` 混用
- 中文算法笔记模板移入 `templates/` 目录
- `.c` 和 `.cpp` 同时存在时：如只是语言不同，保留并标明；如重复，保留较优版本

### 结论

**是，该目录适合进入正式整理阶段。**

理由：
1. 核心问题已明确——主要是**命名格式混乱**（大小写、版本号格式、括号异常）、**少量无效文件**、**多版本冗余**；
2. 绝大多数文件内容有效，不存在大范围的文件损坏或错误；
3. 整理可分为"纯文件名操作"（批量重命名、删除无效文件）和"需读代码操作"（多版本清理、内容一致性验证）两个阶段，前者可先行；
4. 预计 P0-P2 级别的整理可在不读取代码的情况下完成，约影响 <30 个文件；
5. P3-P4 级别涉及多版本清理和内容验证，需要逐题读代码，适合分批次进行。

**建议分两阶段实施：**
- **阶段一（安全操作）**：删除空文件/临时文件/编译产物、重命名异常文件名、统一小写前缀、移走中文笔记
- **阶段二（审慎操作）**：逐题检查多版本文件、确认内容与文件名一致、清理冗余版本
